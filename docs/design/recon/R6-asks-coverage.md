## 0. The ten findings that matter most

1. **F1. The G-03 acceptance cannot be met on the podvm path, and the official runner makes it worse.** The runner takes the JIT blob from `--jitconfig` or `ACTIONS_RUNNER_INPUT_JITCONFIG`, decodes it and writes `.runner`, `.credentials`, `.credentials_rsaparams` into its own root with `File.WriteAllBytes` (Observed: `actions/runner` `src/Runner.Listener/Runner.cs:234-257`, `CommandSettings.cs:111-138`). The Worker child reads `.runner` from disk (`JobRunner.cs:47` calling `GetSettings`, `ConfigurationStore.cs:285-287`). podvm's own entry T-1696 says the "once" rule is served by the interposer and a raw syscall bypasses it (`podvm:TODO/cli.md`, T-1696, Decision). Priority in podvm is P2, although the peer asked P0.
2. **F2. The userland rung is x86_64 only, but the asks need aarch64.** `podvm:docs/limits.md:34`: "The embedded interposer pair is x86_64. Other payload architectures need another execution path." #35 and #36 require x86_64 and aarch64 (`i35.md` rules, `i36.md` rule 6, G-05). #47 treats the .NET runner's arch gap (i686, riscv64, loongarch64, ppc64le) as the arch problem and never mentions this one.
3. **F3. A static `docker` CLI in the golden image (phase 3) is refused or unconfined on a chroot-denied host.** `podvm:docs/limits.md:13-16`: a static payload on such a host "refuses at 125" or, with `--unsafe-host-paths`, "runs ... with the host root"; `:23-26`: a program that issues `syscall` itself "(a static program, Go, liburing) passes the interposer". The Docker CLI, `github-act-runner`, `act_runner`, `gitlab-runner` are Go and static.
4. **F4. Phase 0 depends on a phase 2 item.** #47 phase 0 is "no new code in podcrates", and its first item needs "a TLS end (T-100)". T-100 is open and is a phase 2 item (#47 phase 2, first bullet; `podcrates:TODO/fleet.md` T-100, Status open). The other route needs a GitHub test repository, which the ruling "Test accounts: Not now" forbids as a CI secret.
5. **F5. #47 says phase 0 and the podvm items "can start now". The owner ruled 2026-11-10 "leave #47 alone".** `podcrates:docs/decisions.md` row "CI tracker": "T-146 and the questions Q8 to Q14 wait; no work on the plan of #47 until the owner names it". Also `podvm:TODO/PROGRESS.md` item 16: T-1694 to T-1696 "come after podvm's own work order".
6. **F6. G-01 asks for an HTTPS contract that a forge implements. #47 and the plan build a Rust "job-source trait".** G-01: "the contract as a small HTTPS API that githome implements". #47 phase 4: "The job-source trait and a fake forge in `pod-testkit`". The G-01 payload clause ("starts the runner payload that the source names (an OCI image, a command, and the path at which the credential file appears)") is absent: the plan fixes the payload to the official runner.
7. **F7. A-X-01 names Incus containers, a warm pool and a "Later backends" list. #47 drops Incus, moves warm units to phase 4 and turns the GitLab backend into a different model.** The plan rejects Incus in `s4 Rejected` ("needs root or a KVM group") while its own microVM tier needs `/dev/kvm` for a user in group `kvm` (A-V-08; `podvm:TODO/machine.md` T-1656 amended: a KVM run never falls back to TCG). P12 makes GitLab Runner a long-lived daemon that calls scripts, not an ephemeral payload per job.
8. **F8. `pod-testkit` has no fake GitHub and T-106 says it will not get one.** `podcrates:TODO/fleet.md` T-106: "The fake GitHub API and the fake control plane stay in their projects." Plan P9 puts "A stand-in GitHub (`generate-jitconfig`, broker `sessions`, `message`, `acquirejob`, `renewjob`)" into `pod-testkit`. `podcrates:docs/research/fleet/asks.md` A-X-18: "the new projects own their fakes".
9. **F9. A-X-05 asks for one binary; no repository is assigned to make it.** A-X-05 acceptance: "The acceptance rows of A-N-13 and A-V-03 pass against one binary". Rule C27 (`podcrates:docs/decisions.md`): "A broker binary is a thin `main` in the product that hosts it." The routing page names three hosts: podvm `--net broker` (A-V-03), podssh (A-S-11), podrunner (plan P7). Nobody owns the `podcredproxy serve` CLI.
10. **F10. Stale facts about podvm in the plan and in #47.** (a) `-v` is not "not supported": `podvm:crates/podvm/src/parity.rs:222` is Degraded. (b) T-1643 to T-1649 and T-1697 are done (`podvm:TODO/INDEX.md` rows 320 to 325, 373); the plan s3 says A-V-04 is "open" and T-1697 is a current failure. ### 3.2 Facts about the official runner's credential handling (Observed, upstream `actions/runner` main at the blob sha shown in the forge mirror, read 2026-11-10)

(a) `Runner.cs:234-257`: `command.GetJitConfig()`; the base64 value is decoded as a JSON map of file name to base64 content; each entry is written with `File.WriteAllBytes(Path.Combine(HostContext.GetDirectory(WellKnownDirectory.Root), config.Key), ...)`. The credentials therefore end up as files in the runner root, owned by the runner's uid, with default mode. Every step of the job runs as the same uid.
(b) `CommandSettings.cs:111-138`: an environment variable with prefix `ACTIONS_RUNNER_INPUT_` is read as an argument and removed from the process environment after reading. `GetJitConfig` is `GetArg(name: JitConfig)`: no prompt, no file option.
(c) `JobRunner.cs:47`: the Worker (a child process) calls `IConfigurationStore.GetSettings()`. `ConfigurationStore.cs:285-287` reads `.runner` from disk with `File.ReadAllText`.
(d) Consequences. A `once` rule per file that fails the second read for any child would break `.runner` in the Worker. A rule that applies only to `.credentials` and `.credentials_rsaparams` would hold if the Listener reads them once and caches them. I did not read where `.credentials_rsaparams` is read; Unverified. If podrunner stages the three files (as plan P2 says), it writes the files the runner would write; the plan does not say that `--jitconfig` is then not passed.
(e) Plan s8 risk 4: "`--jitconfig` on the command line shows in `/proc/*/cmdline`; use files or the environment of a process that scrubs it; measure". (b) shows the env route is read then scrubbed by the runner itself; the interval before the scrub is the window.
