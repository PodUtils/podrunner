A beta of podrunner, for tests. It is not for production CI.

podrunner runs each CI job of GitHub in one fresh unit and destroys the
unit after the job. It needs no root, no docker daemon and no user
namespace. Each binary is static (musl).

## What is proven in CI

* `podrunner run workflow.yml` (the local mode, `docs/cli.md`): the
  official runner v2.338.2 runs the jobs of one workflow file, each job
  in a fresh podvm unit with no root. A matrix, `needs`, the outputs of
  jobs, `if:`, `actions/checkout`, a local action, a `container:` job
  and a Docker step pass. With `--podnet PATH`, `podnet pod` holds the
  egress of each unit: a step reaches only the hosts of `--allow HOST`.
* The podvm unit driver: the unit conformance suite passes, with and
  without the confine layer of podvm, on x86_64. The runner image starts
  on x86_64 and aarch64. A musl build of the runner runs a job in a
  podvm unit on both.
* `podrunner serve`, the JIT mint, the slots, the scale-set sidecar and
  the remote mint (`podrunner mint-serve`) pass their tests against fake
  services.

## What is not proven

* No job of real github.com ran yet. The live gates (T-032, T-033,
  T-040) start with this beta on a test organization.
* The `microvm` kind (a guest of the machine tier of podvm) is not in
  this beta (T-037). With no guest kind, the `untrusted` tier (a fork
  pull request) runs no job.

## The files

| File | What it is |
| --- | --- |
| `podrunner-x86_64-unknown-linux-musl` | podrunner, Linux x86-64 |
| `podrunner-aarch64-unknown-linux-musl` | podrunner, Linux ARM64 |
| `scaleset-sidecar-x86_64-unknown-linux-musl` | the sidecar of a `github-scaleset` source, Linux x86-64 |
| `scaleset-sidecar-aarch64-unknown-linux-musl` | the sidecar, Linux ARM64 |

Each file has a `.sha256` file and a build provenance attestation.

```sh
sha256sum -c podrunner-x86_64-unknown-linux-musl.sha256
gh attestation verify podrunner-x86_64-unknown-linux-musl --repo PodUtils/podrunner
```

A unit also needs:

* podvm `v0.2.0-beta.7` (`images/podvm.toml` gives the SHA-256 of each
  binary);
* podnet `v0.4.0-beta.8` for the egress hold (`images/podnet.toml`);
* the runner image: build it with `images/runner/Dockerfile`, or take
  the archive `runner-x86_64` or `runner-aarch64` of the
  `runner-image.yml` run of the tagged commit, and `podvm load` it.

## Report a problem

Open an issue in `PodUtils/podrunner` with the command, its output, and
the output of `podrunner doctor --json`. Do not put a key, a token or a
credential file in the issue.
