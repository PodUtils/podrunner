# The command line

`crates/podrunner/src/cli.rs`. The exit codes are the table of `pod-core`
of podcrates: 0 success, 64 a usage error (also a file of an option of
`run` that is not there, such as `--event-path`), 66 a file that does not
exist or cannot be read (the workflow of `run`, `audit verify --file`,
`fake-source --script`; the account of `install-unit` that the host
does not know), 69 a control
socket that does not answer or a state directory that another `serve`
holds, 75 a `stop --wait` that timed out, 76 an audit file whose chain
breaks or a local run whose loop stops, 77 a refusal of the supervisor (also
`install-unit` and `remove-unit` by a caller that is not root), 78
a configuration that cannot be used, 80 a kind, a source or a hold that
this build or command has not.

`docs/install.md` gives the installer of the local mode
(`podrunner-install.sh` of a release, `scripts/install.sh`).

| Command | What it does |
| --- | --- |
| `podrunner serve --config FILE --state DIR [--socket PATH]` | Run the slots: one tick each second, and the control socket (`DIR/ctl.sock` by default, mode 0600). It first takes the lock `DIR/serve.lock` (a `flock`; the file stays): a second `serve` on one state directory exits 69 before it reads the journal. A live socket at the path is never replaced. SIGTERM and SIGINT start the drain of `stop`. With `NOTIFY_SOCKET` it sends `READY=1` when the socket answers, `STOPPING=1` at the drain, and `WATCHDOG=1` at half of `WATCHDOG_USEC`. |
| `podrunner check --config FILE` | Check a configuration as `serve` does before it starts, with no side effect: each table and key (an unknown key or a wrong type exits 78 and names it), each source built and not called (key files, certificates, the sidecar file), each unit kind with its driver file, and each pin of this architecture whose `unpacked_bytes` is over the root disk of `[unit.incus]` (`root_quota` and `disk_max_bytes`, T-551) or over `(mem - 512 MiB) × 4 / 13` of `[unit.microvm]` (8G when absent: the root of a guest is an uncompressed initramfs, and podvm needs 13/4 times the image plus 512 MiB, T-573), with the fix. No state directory, no unit, no network. `serve` refuses a bad file with the same text. `docs/examples/podrunner.toml` passes it in the gate. A file with `cert_file` is a file of `mint-serve`: `check` reads it as the mint does (its keys, its source, the key file of the mint at mode 0600 and its certificate). In both files, each trust table that lists `pull_request_target` in `extra_events` (the owner, Q12) gives one line `podrunner: TABLE: extra_events: pull_request_target is trusted ...` on stderr, and `serve` and `mint-serve` print it at their start; `other` and `unknown` in `extra_events` exit 78 (T-518). Each `github-scaleset` source with `allow_personal_account = true` gives one line `podrunner: [[source]] NAME: allow_personal_account: ...` on stderr that names the extra repository permission of the App, "Administration: write" (`[source]` in a file of `mint-serve`); `serve` and `mint-serve` print it at their start; the key on another kind of source exits 78 (T-504). A `config_url` of a `github-scaleset` source that no scale set serves (a query, a fragment, a user, a `.git` at the end, an enterprise, a part that is not a name), the key with the URL of one part, and an `api_url` that is not the API of `config_url` exit 78. |
| `podrunner status [--json] (--state DIR \| --socket PATH)` | The status (`status.v1` of `pod-job`, `schemas/status.v1.schema.json` of podcrates): each source with its jobs and refusals, each kind with its record, each pin with its age, `degraded`, `no-tier-served`. Text from a file or a forge prints with each control character as an escape, cut at 200 bytes. |
| `podrunner drain ...` | Take no new job; the jobs in flight go on. |
| `podrunner drain --source NAME ...` | The source NAME takes no new job; its jobs in flight and each other source go on; `status --json` names it `draining` (T-501). A name that is no source exits 77. |
| `podrunner stop --source NAME ...` | Drain the source NAME; when its last job ends, its program ends (its place gives no event and refuses each call), and `serve` writes one line. Each other source goes on (T-501). |
| `podrunner resume --source NAME ...` | The source NAME takes jobs again; a stopped source is built again from its `[[source]]` table first (as `source restart`). |
| `podrunner stop ...` | Drain, then end when each job is final. |
| `podrunner stop --wait --state DIR [--timeout SECONDS]` | Also wait until `serve` has ended (the lock of `DIR` is free). A timeout exits 75. |
| `podrunner clear-degraded ...` | Start jobs again after the operator looked at a residue. |
| `podrunner config init --source NAME --program PATH [--arg ARG]... [--key-file FILE] [--tier trusted\|untrusted] [--org LOGIN]... [--user LOGIN]... --podvm PATH --images STORE [--podnet PATH] --image NAME@sha256:HEX --built-at-s N [--runner-version V] [--unpacked-bytes N] [--slots N] [--kinds auto\|LIST] [--host NAME] --out FILE [--json]` | Write a `podrunner.toml` for `serve` with one `program` source, the unit kinds of LIST (`microvm`, `incus`, `podvm`; `auto` tries each) that this host can run (the probe of `doctor`; the incus kind also needs a socket of incusd that takes a connection, found as podvm finds it: `PODVM_INCUS_SOCKET`, else `unix.socket` of `INCUS_DIR`, else of `/var/lib/incus`), the trust lists, and the pin of IMAGE (`built_at_s` is the time of the build of the image and `unpacked_bytes` its unpacked size: `podrunner-manifest.json` of a release has both, T-572). A kind whose bound the image exceeds (T-551, T-573) is refused with the fix. A trusted source gets `confine = true` on the podvm kind, and the kind only when the self-test of the confine layer (the one of `serve`, with the hold and IMAGE) passes here; else `refused` names its cause (T-565). The file is at mode 0600, `check` takes it, and it opens no TCP listener (T-507). With `--json`, one line `{"file", "kinds", "refused": [{"kind", "why"}], "changed"}`. A second run with the same input writes nothing (`changed` false). Exit 0; 64 for a bad flag; 78 when no kind runs here or `check` refuses the file (no file is written); 77 when FILE holds another text. |
| `podrunner source restart --name NAME ...` | Build the source `NAME` again from its `[[source]]` table, with its key file of now (a new key of a program source: its program starts again), and keep each job of the source: no drain (T-498). A source that does not build or refuses `hello` keeps the old one, and the command exits 77 with the cause. A source that answered `source-revoked` gets no job (`revoked` in `status`) and starts again by itself when its key file changes: one try for each change. |
| `podrunner audit verify (--state DIR \| --file FILE) [--anchor SEQ:HASH]` | Walk the chain of `audit.jsonl`: each line has `seq` and `prev` (the SHA-256 of the line before). A lost, edited or torn line exits 76 and names the `seq`. A cut tail needs the anchor: the `seq` of a line and the `prev` of the next line in the copy at the source. |
| `podrunner doctor [--config FILE] [--json]` | With the file: the capability record of each unit kind through its driver binary, the hold of `[unit.podvm] podnet`, and for each source whether a kind meets the floor and the hold of its tier; each source has the list `extra_permissions` (`["Administration: write"]` with `allow_personal_account`, else empty), and with the key its line ends with `; the App needs Administration: write (allow_personal_account)` (T-504). Always: the Landlock ABI, `/dev/kvm`, and the rows of `pod-hostprobe` that the drivers need (user namespaces, mount, chroot, KVM, Landlock), each in a disposable child of the binary. With the file it also names each pinned payload: the version of its runner, its age and its window (the age limit of the pin), `stale`, or `near-end` in the last 7 days of the window; and the runner that this build pins (T-499). With `unpacked_bytes`, a pin names the size of its image and, with an incus kind, the host disk that it needs: the extracted tree plus about 2.4 times it in incusd (podvm's measure); with a microvm kind, the memory of a guest that boots it (13/4 times the size plus 512 MiB, T-573); a pin over the bound of a kind is missing, as `check` refuses it (T-551). It names each input that is missing and changes nothing (call C9). |
| `podrunner doctor [--json] --run FILE [the options of run]` | The checks of a local run before it starts (T-153), with the flags of the configuration files of `run` first, as `run` takes them (T-143, T-202): the limit of file size (T-144), the free disk of the scratch directory, the workflow and its lock file, the runner directory, the podvm binary and its lowest version for the kind, the store, `/dev/kvm` for `--microvm`, the engine directory and podnet. One line for each check: `ok` or `FAIL` with its fix; with `--json` (before or after `--run`), one object `{"ok", "checks": [{"name", "ok", "text"}]}` (T-342). Nothing changes. Exit 0, or 1 when a check fails. |
| `podrunner print-unit --config FILE --state DIR [--binary PATH] [--watchdog SECONDS]` | A user unit of systemd for `serve`, from `pod_unit::systemd::render` of podcrates (T-576): `Type=notify`, a stop that waits for the drain (`KillMode=mixed`, `TimeoutStopSec=infinity`), `Restart=on-failure` but not after 64 or 78, and the lines of seccomp of the hardening of `pod-unit`. A line that a driver or a job cannot take is a comment with its reason: `RestrictNamespaces`, `MemoryDenyWriteExecute`, `SystemCallArchitectures`, `SystemCallFilter`, `RestrictAddressFamilies`, `UMask` and `LockPersonality` (`setarch i386`, T-588). The unit keeps `NoNewPrivileges` and `RestrictSUIDSGID`: a process of the host cannot gain a privilege by `sudo` or a setuid file (`docs/decisions.md`, T-588). The unit holds no credential: `pod-unit` refuses a word that looks like a secret, exit 64. `WatchdogSec` only with `--watchdog`. `--config` must be a file; `--config` and `--state` must be absolute paths, as systemd starts `serve` in the home (a user unit) or in `/` (a unit of the system), else exit 64 (T-588); `--binary` (default `/usr/local/bin/podrunner`) must be an absolute path; each value is one word of `ExecStart` (double quotes for a space or a quote, `%%` and `$$`), and a control character is refused, exit 64 (T-343). |
| `podrunner print-unit --system [--user NAME] --config FILE --state DIR [--binary PATH] [--watchdog SECONDS]` | A unit of the system for `serve` (T-588), for `/etc/systemd/system/podrunner.service`: the unit of the row above, with `User=NAME` (default `podrunner`; `serve` gets the groups of the account, such as the group of `/dev/kvm`), `WantedBy=multi-user.target`, `Delegate=yes` and `DelegateSubgroup=serve` (podvm makes the cgroup of a unit beside the cgroup of `serve`, in the subtree of the account), and `StateDirectory=NAME` when `--state` is `/var/lib/NAME` and NAME is 1 to 64 of `A-Z a-z 0-9 _ . -`, not first `.` or `-` (systemd then makes the directory, gives it and its files to the account, and sets mode 0700; for each other `--state` the operator makes the directory). `pod_unit::systemd::audit` of a unit of the system passes: the unit keeps `NoNewPrivileges`, `AmbientCapabilities=`, `RestrictSUIDSGID`, `ProtectKernelModules`, `RestrictRealtime` and `RemoveIPC`, and each other line is a comment with its reason (`docs/decisions.md`, T-588). `NAME` is 1 to 32 of `A-Z a-z 0-9 _ . -`, first a letter or `_`; `root` and a number are refused, exit 64. `--user` with no `--system` exits 64. |
| `podrunner install-unit --system [--user NAME] --config FILE --state DIR [--binary PATH] [--watchdog SECONDS]` | As root: write the unit of `print-unit --system` to `/etc/systemd/system/podrunner.service`, then `systemctl daemon-reload`, `enable` and `restart` (`pod_unit::install::install_system`). The checks come before any write: a caller that is not root exits 77; a host where systemd is not the service manager exits 69; an account that `id -u` does not know exits 66; an account of uid 0 exits 64; a file of the same name with no mark of podrunner stays, exit 78. A unit that does not start is disabled and removed, exit 69. The account and the state directory are the operator's: make them first. With no `--system`, exit 64. A second run writes the unit again and restarts `serve`. After the start, a systemd older than 254 (from `systemctl --version`) gets a line on stderr: it ignores `DelegateSubgroup=`, and podvm then holds no CPU limit; the exit stays 0. |
| `podrunner remove-unit --system` | As root: `systemctl disable --now podrunner.service`, then remove `/etc/systemd/system/podrunner.service`, only when the file has the mark of podrunner (else exit 78, and it stays). With no such file: exit 0, nothing to remove. The state directory and the configuration stay. A caller that is not root exits 77. |
| `podrunner image verify --tarball FILE --arch ARCH` | Check a release tarball of the official runner against `images/runner/runner.toml` (the version and the SHA-256 of each architecture). The file is `actions-runner-linux-ARCH-VERSION.tar.gz` of actions/runner (ARCH `x64` or `arm64`), not the runner image `runner-ARCH.tar` of a release (check that one with `sha256sum -c` and its `.sha256` file). Exit 78 when it differs: the error names the file and the SHA-256 of the pin, and says when the file is a runner image (T-344). |
| `podrunner run (FILE \| DIR) (--runner-dir DIR \| (--podvm PATH [--podnet PATH \| --vnet PATH] \| --microvm PATH [--engine DIR] \| --incus PATH [--engine DIR]) --images STORE --image NAME@sha256:HEX) [--allow HOST]... [--platform LABEL=NAME@sha256:HEX\|host]... [--actions DIR] [--offline \| --frozen] [--artifacts DIR] [--cache DIR \| --no-cache] [--secret NAME]... [--secret-file FILE] [--github-token-env NAME] [--job ID]... [--matrix KEY=VALUE]... [--list \| --graph \| --validate \| --dry-run] [-q] [--json] [--log-dir DIR] [--environment-secret-file NAME=FILE]... [--environment-var-file NAME=FILE]... [--environment-allow NAME=HOST]... [--protected NAME]... [--approve NAME]... [--export DIR] [--toolcache DIR] [--local-repository OWNER/REPO@REF=DIR]... [--action-server URL] [--oidc-issuer URL] [--oidc-keys FILE] [--watch \| --schedule] [--no-config] [--changed-since REF] [--web IP:PORT] [--jobs N] [--break JOB:STEP]... [--break-on-failure \| --keep-failed] [--state DIR] [--rerun DIR [--failed \| --job ID]... [--refresh]] [--checkout DIR [--checkout-head] [--with-git | --no-git]] [--event NAME] [--event-path FILE] [--force-event] [--remote NAME] [--ref REF] [--sha SHA] [--repository OWNER/REPO] [--actor NAME] [--var NAME=VALUE]... [--input NAME=VALUE]... [--var-file FILE] [--input-file FILE] [--env NAME=VALUE]... [--env-file FILE]` | The local mode (T-046): run the jobs of one workflow file, with no forge, against a fake broker on the loopback, one job at a time. With `--runner-dir`, DIR is an unpacked release of the official runner that the run may change; each job runs in it as the user of podrunner. A job there takes `PATH`, the proxy variables and the CA files of the environment, with the loopback in `NO_PROXY`, and a scratch `HOME` in `_work/_home` (`docs/local-mode.md`, "A host with a proxy"; T-265, T-266). With `--podvm`, each job runs in a fresh podvm unit of the runner image IMAGE of the store STORE (T-090), and a unit with residue fails its job. `needs`, a matrix with `fail-fast`, `if:`, the `continue-on-error` of a job and the outputs of jobs hold as on GitHub; `--event` (default `push`), `--var` and `--input` give `github.event_name`, `vars` and `inputs`. Before the first job, each `uses: OWNER/REPO[/PATH]@REF` (a tag, a branch or a commit) of the workflow, and of each composite action that it names (also a local one, `uses: ./PATH` of the checkout, to 10 levels, T-346), is pinned by `podrunner-actions.lock` beside the workflow: one line `OWNER/REPO@REF COMMIT sha256:HEX` for each reference, with the SHA-256 of the tar of the commit (T-118). The host resolves a reference that the lock does not have with `git ls-remote` on github.com, fetches the commit, writes the lock, and keeps the tarball in the store `--actions DIR` (default `$XDG_CACHE_HOME/podrunner/actions` or `~/.cache/podrunner/actions`) as `DIR/OWNER_REPO/SHA.tar.gz`. A tag of the lock that moved, or a tarball whose SHA-256 differs from the lock, fails the run by name. `--frozen` refuses a change of the lock; `--offline` uses the lock and the store only and fetches nothing. A unit never fetches an action. The host fetches through one grant of the egress module whose policy allows the host of the forge only (T-154): git takes a loopback relay to the grant as its only proxy, and only the protocol of the forge (no submodule, no `file://` or `ssh://`); the way out of the module is the proxy that the environment names for the forge, or a direct connection; a redirect to another host gets 403. With a unit kind, each image of `container:`, `services:` and `docker://` steps that a tag names is pulled into STORE by `podvm pull` before the first job and pinned in the same lock (`docker://NAME:TAG sha256:HEX`); the runner gets `NAME@sha256:HEX`; a tag that moved fails by name; `--offline` and `--frozen` hold as for the actions (T-130). Each broker of the run serves the ArtifactService of `actions/upload-artifact@v4` and `actions/download-artifact@v4` over one store for each run (T-119): a job downloads the artifact of an earlier job; a name is unique in a run; the finalize checks the size and the SHA-256; a run holds at most 4 GiB of artifacts. `--artifacts DIR` keeps the store after the run, as `DIR/NAME/artifact.zip` and `DIR/NAME/artifact.json`; a new run (no `--rerun`) removes the artifacts of an earlier run from DIR first and names them on stderr, and with `--state` the state names DIR, so that `--rerun` reads it (T-334, T-335); with no `--artifacts`, the store goes with the run. v3 and older of the artifact actions are refused by name, as GitHub refuses them since 2025-01-30. Each broker also serves the CacheService (cache service v2) of `actions/cache@v4` and of the cache of the `setup-*` actions over a store that stays across runs (T-120): `--cache DIR`, by default `$XDG_CACHE_HOME/podrunner/cache` or `~/.cache/podrunner/cache`; `--no-cache` turns it off: each lookup is a miss and each save is refused at once (T-338). A lookup takes the exact key, then each restore key as a prefix, newest first, of the same version; an entry is written once; the oldest entry goes when the store is over 10 GB. The `github` context comes from the git tree of `--checkout`, or of the current directory (T-125): `repository` from the URL of the remote `--remote NAME` (default `origin`), `ref` and `sha` from HEAD (a detached HEAD on a tag gives `refs/tags/TAG`; else the default branch), `actor` from `user.name`, `workflow` from the `name:` of the workflow, else its path, and `workflow_ref` from its path at the ref (T-426); `--repository`, `--ref`, `--sha` and `--actor` replace each one. `github.event` is the JSON of `--event-path FILE`, or a minimal payload of the event as GitHub sends it; a `pull_request` runs on `refs/pull/1/merge` with `head_ref` and `base_ref`. A workflow whose `on:` does not take the event after its filters (`types`, `branches`, `tags`, `paths` and their `-ignore` forms, as GitHub decides) is refused, unless `--force-event`: the activity type comes from the payload, the ref from the tree (the base branch for a pull request), and the changed files from `git diff --name-only REF` of `--changed-since REF` with each new file that git does not ignore (T-430) (with no `--changed-since`, a `paths` filter does not apply). A REF or a `--remote NAME` that starts with `-` is refused with exit 64: git reads it as an option (T-631). With a directory in place of FILE, each workflow of it (`*.yml`, `*.yaml`, by name) that takes the event runs, one after the other, each with the line `--- NAME`; a workflow that does not take it gets one line (T-125). Each directory of `--artifacts`, `--state`, `--log-dir`, `--export` and `--rerun` holds a directory `NAME` for each workflow (T-428). The cache keeps each entry in the scope of the ref; a lookup reads the scope of the ref, then that of the default branch. The secrets of the run come from `.secrets` of the `--checkout` tree, else of the current directory, when it exists (with each check of a secret file, also in a dry run, T-341), then `--secret-file FILE`, then each `--secret NAME` (the value of the variable NAME of the environment; a value in argv is refused) (T-121). A secret file has one `NAME=VALUE` on each line, or `NAME<<DELIM`, the lines of the value and `DELIM`, as `GITHUB_ENV` (as the runner, a line is `NAME<<DELIM` only when `<<` comes before the first `=`, T-429), and needs mode 0600 or less; a name cannot start with `GITHUB_`. Each secret is a secret variable of the job message: the steps read it as `secrets.NAME`, and the runner masks it in the logs. `github.token` and `secrets.GITHUB_TOKEN` are a made-up token; an action that gives it to the API of a real forge (`setup-node` for the manifest of an LTS alias) fails with "Bad credentials" (`raw.githubusercontent.com` answers 404, as for the manifest of `setup-python`), and the run names the fix (T-254, T-269); a variable NAME that is empty sends no token, which is enough for public data; `--github-token-env NAME` gives the token of the variable NAME to each job whose `permissions` are not `{}` (T-122). podrunner reads no token of a CLI. `--checkout DIR` gives the tree DIR to each `uses: actions/checkout@REF` (T-133); with no `--checkout`, a workflow that uses it (also in a workflow of `./PATH` that it calls, to 10 levels; a call of another repository takes the tree when there is one, T-421) takes the top of the git tree of the current directory, or out of a git tree the project whose `.github/workflows` holds the file, with a line on stderr; with neither, the run is refused with the fix (T-203, T-336, T-337): in a git tree each tracked file and each new file that git does not ignore, at its state on disk; `--checkout-head` gives the committed files of HEAD only; a git tree gets a `.git` (a clone of the tree with an index of HEAD), so that `git` works in a step, as on GitHub; `--no-git` leaves it out (T-267); `--with-git` asks for it and fails out of a git tree; out of a git tree each file of DIR. A checkout of a git tree keeps the submodules of its `submodules:` (`true`: the first level; `recursive`: each level) with their tracked files on disk (with `--checkout-head`, at the commit that HEAD records), and leaves each other submodule an empty directory, as GitHub does; a submodule that it keeps and that has no files (no `git submodule update --init`) fails the step with the fix; `submodules` with a checkout of another repository is refused, as the store keeps no submodule (T-425). The checkout never holds `.secrets` of the tree, a file of `--secret-file`, `--env-file` or `--var-file` in the tree, or a `podrunner-actions.lock` that is not committed; a committed lock stays, at its state on disk (with `--checkout-head`, as committed) (T-268, T-276, T-339). A checkout of another repository (`with: repository:` and `ref:`, plain values; no `ref` is HEAD of its default branch) takes the tree of that repository from the store at the commit of the lock, as an action;, which unpacks it into the workspace or into a plain relative `with: path:`; a `./` action reads the checked-out tree. With `--podvm`, where podvm gives container hooks on the host (`podrunner doctor --run` names it; else the run, the dry run and the doctor say to use `--microvm --engine`, T-311), `container:` and Docker steps (`uses: docker://NAME@sha256:HEX`) run through the container hooks of the unit; a Docker step also runs in a job with no `container:` (as on GitHub), and the runner splits its `args` at each space, so a quoted argument with a space breaks; each image must be pinned by digest and be in STORE. Each podvm unit of the local mode is on the host network, so the hook server refuses `services:` and port mappings, and that job fails. A dry run on `--podvm` refuses such a job too, and each runner image of the run (`--image`, the images of `--platform`) must be in STORE: a missing one fails the run with the fix, and no registry is asked (T-272). With `--runner-dir` a job with containers fails, also in a dry run (T-218), and so does a job with an action of `runs.using: docker`, also in a composite action (T-270); a job that runs past its `timeout-minutes` (at most 5 days, the limit of a job of a self-hosted runner on GitHub, #224) ends with the process group of its runner and fails, and a runner that a limit of file size ends (SIGXFSZ) fails its job by name (T-115, T-144). In a unit, a runner that sends no request to its broker in 600 s fails its job with that cause (it cannot reach the broker), not at its `timeout-minutes` (T-561). Each of these fails its job before it runs, with the reason: an image that is not pinned by digest. A job with containers that the executor of the run cannot run (a runner directory; podvm with no container hooks; `services:` on podvm; a guest with no `--engine`) fails by that cause before the pin and the pull of its images, and the run checks `/dev/kvm` of `--microvm` before any pull (T-327, T-330). A job that calls a reusable workflow (`jobs.ID.uses: ./PATH` of the tree, or `OWNER/REPO/PATH@REF`, pinned by the lock; a `./PATH` comes from `--checkout DIR`, else from the tree of the project, T-421, and kept in the store as an action) runs the jobs of that workflow as jobs of the run, named `CALLER / CALLEE`, with the inputs of `on.workflow_call.inputs` (checked, with their defaults), only the secrets that the call passes (each secret of the run with `secrets: inherit`), and the outputs of `on.workflow_call.outputs` as `needs.CALLER.outputs`; a matrix of calls and nested calls hold, to the limits of GitHub (10 levels, 50 workflows) (T-131). An `env:` of the workflow, of a job or of a step can be one expression that gives a mapping (`env: ${{ fromJSON(vars.ENV) }}`): the runner evaluates it, as the schema of the runner allows (T-152); another text in place of the mapping fails its job. The steps read the `github` context of the run: `--event` gives `github.event_name` (T-114). With `--microvm PATH` or `--incus PATH`, each job runs in a fresh guest of the microvm kind or in a fresh incus instance (each with the engine of `--engine DIR` for its containers; incus needs podvm `0.2.0-beta.32`, T-485), built as `serve` builds `[unit.microvm]` and `[unit.incus]`, with the same lowest version of podvm (T-123). A guest has no NIC: a front on its egress socket gives the fake broker (`broker.podrunner.test`), and the hosts of `--allow` through the egress module; each other host gets 403. ## The control socket

The control API of `pod-control` of podcrates, protocol 1
(`schemas/control.v1.schema.json` of podcrates `v0.80.0`; T-576): JSON
lines on a unix socket of mode 0600. A peer with another uid is refused.
The socket has threads of its own: at most 8 clients at a time (one more
gets `busy`), a line of at most 64 KiB, 5 s for each line and 5 s for the
answer of the supervisor, so a silent client delays no tick of the
supervisor. While the supervisor waits on a source, `status` gets the
last status and another method gets `busy`. A connection can send more
than one request.

A request is one line,
`{"schema": 1, "id": N, "method": NAME, "params": {...}}`; the answer is
`{"schema": 1, "id": N, "ok": true, "result": ...}` or
`{"schema": 1, "id": N, "ok": false, "error": {"code": CODE, "detail": WORDS}}`.
The codes: `bad-request`, `not-utf8`, `too-long`, `unknown-method`,
`bad-params`, `refused`, `busy`, `budget`, `timeout`, `unsupported`,
`failed`, `internal`.

| Method | Tier | Params | What |
| --- | --- | --- | --- |
| `version` | read | none | `{"program": "podrunner", "version": ..., "protocol": 1}`. |
| `methods` | read | none | The methods that the caller can call, with its tier. |
| `auth` | read | `{"token"}` | `refused`: `serve` has no master token. |
| `status` | read | none | `status.v1`. |
| `metrics` | read | none | Gauges (`slots`, `busy`, `units`, `draining`, `degraded`, `no_tier_served`, `spooled_reports`, `jobs_STATE`) and counters (`refused_WHY`, `ended_without_completion`). |
| `reload` | master | none | `unsupported`: `restart-source` builds one source again. |
| `drain` | operate | `{"exit": BOOL}` | `exit: false` (`podrunner drain`): take no new job. `exit: true`, the default (`podrunner stop`): take no new job, then exit after the last job. |
| `stop` | operate | none | As `drain` with `exit: true`. |
| `capacity` | read | none | The free slots of all unit kinds. |
| `clear-degraded` | operate | none | Start jobs again. |
| `withdraw` | operate | `{"job_id"}` | `unsupported` (GitHub #29). |
| `drain-source`, `resume-source`, `stop-source` | operate | `{"source"}` | `podrunner drain`, `resume` and `stop` with `--source`. |
| `restart-source` | master | `{"source"}` | `podrunner source restart`. |

A peer of the uid of `serve` has the master tier, so each command of
this page can call each method. A method above the tier of a caller
answers as a method that is not there (`unknown-method`). The command
line prints the `result` as JSON; an `error` exits 77 with its code and
its detail. A test runs `pod_control::conformance::check` against the
socket of `serve` (`crates/podrunner/tests/serve.rs`).

Where units run as the uid of podrunner (a shared principal), the peer
check does not protect the socket from a unit.
