# The command line

`crates/podrunner/src/cli.rs`. The exit codes are the table of `pod-core`
of podcrates: 0 success, 64 a usage error, 66 a file that does not exist
(`run`, `audit verify --file`, `fake-source --script`), 69 a control
socket that does not answer or a state directory that another `serve`
holds, 75 a `stop --wait` that timed out, 76 an audit file whose chain
breaks or a local run whose loop stops, 77 a refusal of the supervisor, 78
a configuration that cannot be used, 80 a kind, a source or a hold that
this build or command has not.

| Command | What it does |
| --- | --- |
| `podrunner serve --config FILE --state DIR [--socket PATH]` | Run the slots: one tick each second, and the control socket (`DIR/ctl.sock` by default, mode 0600). It first takes the lock `DIR/serve.lock` (a `flock`; the file stays): a second `serve` on one state directory exits 69 before it reads the journal. A live socket at the path is never replaced. SIGTERM and SIGINT start the drain of `stop`. With `NOTIFY_SOCKET` it sends `READY=1` when the socket answers, `STOPPING=1` at the drain, and `WATCHDOG=1` at half of `WATCHDOG_USEC`. |
| `podrunner check --config FILE` | Check a configuration as `serve` does before it starts, with no side effect: each table and key (an unknown key or a wrong type exits 78 and names it), each source built and not called (key files, certificates, the sidecar file), each unit kind with its driver file. No state directory, no unit, no network. `serve` refuses a bad file with the same text. `docs/examples/podrunner.toml` passes it in the gate. |
| `podrunner status [--json] (--state DIR \| --socket PATH)` | The status (`schemas/status.v1.json`): each source with its jobs and refusals, each kind with its record, each pin with its age, `degraded`, `no-tier-served`. Text from a file or a forge prints with each control character as an escape, cut at 200 bytes. |
| `podrunner drain ...` | Take no new job; the jobs in flight go on. |
| `podrunner stop ...` | Drain, then end when each job is final. |
| `podrunner stop --wait --state DIR [--timeout SECONDS]` | Also wait until `serve` has ended (the lock of `DIR` is free). A timeout exits 75. |
| `podrunner clear-degraded ...` | Start jobs again after the operator looked at a residue. |
| `podrunner audit verify (--state DIR \| --file FILE) [--anchor SEQ:HASH]` | Walk the chain of `audit.jsonl`: each line has `seq` and `prev` (the SHA-256 of the line before). A lost, edited or torn line exits 76 and names the `seq`. A cut tail needs the anchor: the `seq` of a line and the `prev` of the next line in the copy at the source. |
| `podrunner doctor [--config FILE] [--json]` | With the file: the capability record of each unit kind through its driver binary, the hold of `[unit.podvm] podnet`, and for each source whether a kind meets the floor and the hold of its tier. Always: the Landlock ABI, `/dev/kvm`, and the rows of `pod-hostprobe` that the drivers need (user namespaces, mount, chroot, KVM, Landlock), each in a disposable child of the binary. It names each input that is missing and changes nothing (call C9). |
| `podrunner print-unit --config FILE --state DIR [--binary PATH] [--watchdog SECONDS]` | A systemd unit for `serve` (`Type=notify`, a stop that waits for the drain), with no credential. `WatchdogSec` only with `--watchdog`. |
| `podrunner image verify --tarball FILE --arch ARCH` | Check a release tarball of the official runner against `images/runner/runner.toml` (the version and the SHA-256 of each architecture). Exit 78 when it differs. |
| `podrunner run FILE (--runner-dir DIR \| (--podvm PATH [--podnet PATH] \| --microvm PATH [--engine DIR] \| --incus PATH) --images STORE --image NAME@sha256:HEX) [--allow HOST]... [--actions DIR] [--offline \| --frozen] [--artifacts DIR] [--cache DIR \| --no-cache] [--secret NAME]... [--secret-file FILE] [--github-token-env NAME] [--checkout DIR] [--event NAME] [--var NAME=VALUE]... [--input NAME=VALUE]...` | The local mode (T-046): run the jobs of one workflow file, with no forge, against a fake broker on the loopback, one job at a time. With `--runner-dir`, DIR is an unpacked release of the official runner that the run may change; each job runs in it as the user of podrunner. With `--podvm`, each job runs in a fresh podvm unit of the runner image IMAGE of the store STORE (T-090), and a unit with residue fails its job. `needs`, a matrix with `fail-fast`, `if:`, the `continue-on-error` of a job and the outputs of jobs hold as on GitHub; `--event` (default `push`), `--var` and `--input` give `github.event_name`, `vars` and `inputs`. Before the first job, each `uses: OWNER/REPO[/PATH]@REF` (a tag, a branch or a commit) of the workflow, and of each composite action that it names, is pinned by `podrunner-actions.lock` beside the workflow: one line `OWNER/REPO@REF COMMIT sha256:HEX` for each reference, with the SHA-256 of the tar of the commit (T-118). The host resolves a reference that the lock does not have with `git ls-remote` on github.com, fetches the commit, writes the lock, and keeps the tarball in the store `--actions DIR` (default `$XDG_CACHE_HOME/podrunner/actions` or `~/.cache/podrunner/actions`) as `DIR/OWNER_REPO/SHA.tar.gz`. A tag of the lock that moved, or a tarball whose SHA-256 differs from the lock, fails the run by name. `--frozen` refuses a change of the lock; `--offline` uses the lock and the store only and fetches nothing. A unit never fetches an action. Each broker of the run serves the ArtifactService of `actions/upload-artifact@v4` and `actions/download-artifact@v4` over one store for each run (T-119): a job downloads the artifact of an earlier job; a name is unique in a run; the finalize checks the size and the SHA-256; a run holds at most 4 GiB of artifacts. `--artifacts DIR` keeps the store after the run, as `DIR/NAME/artifact.zip` and `DIR/NAME/artifact.json`; with no `--artifacts`, the store goes with the run. v3 and older of the artifact actions are refused by name, as GitHub refuses them since 2025-01-30. Each broker also serves the CacheService (cache service v2) of `actions/cache@v4` and of the cache of the `setup-*` actions over a store that stays across runs (T-120): `--cache DIR`, by default `$XDG_CACHE_HOME/podrunner/cache` or `~/.cache/podrunner/cache`; `--no-cache` turns it off. A lookup takes the exact key, then each restore key as a prefix, newest first, of the same version; an entry is written once; the oldest entry goes when the store is over 10 GB. `github.ref` is `refs/heads/main`. The secrets of the run come from `.secrets` of the `--checkout` tree when it exists, then `--secret-file FILE`, then each `--secret NAME` (the value of the variable NAME of the environment; a value in argv is refused) (T-121). A secret file has one `NAME=VALUE` on each line, or `NAME<<DELIM`, the lines of the value and `DELIM`, as `GITHUB_ENV`, and needs mode 0600 or less; a name cannot start with `GITHUB_`. Each secret is a secret variable of the job message: the steps read it as `secrets.NAME`, and the runner masks it in the logs. `github.token` and `secrets.GITHUB_TOKEN` are a made-up token; `--github-token-env NAME` gives the token of the variable NAME to each job whose `permissions` are not `{}` (T-122). podrunner reads no token of a CLI. `--checkout DIR` gives the tree DIR (`git archive` of HEAD in a git tree) to each `uses: actions/checkout@REF`, which unpacks it into the workspace or into a plain relative `with: path:`; a `./` action reads the checked-out tree. With `--podvm`, `container:` and Docker steps (`uses: docker://NAME@sha256:HEX`) run through the container hooks of the unit; a Docker step also runs in a job with no `container:` (as on GitHub), and the runner splits its `args` at each space, so a quoted argument with a space breaks; each image must be pinned by digest and be in STORE. Each podvm unit of the local mode is on the host network, so the hook server refuses `services:` and port mappings, and that job fails. With `--runner-dir` a job with containers fails; a job that runs past its `timeout-minutes` ends with the process group of its runner and fails, and a runner that a limit of file size ends (SIGXFSZ) fails its job by name (T-115, T-144). Each of these fails its job before it runs, with the reason: a reusable workflow (`jobs.ID.uses`), an `env:` that is one expression, an image that is not pinned by digest. The steps read the `github` context of the run: `--event` gives `github.event_name` (T-114). With `--microvm PATH` or `--incus PATH`, each job runs in a fresh guest of the microvm kind (with the engine of `--engine DIR` for its containers) or in a fresh incus instance, built as `serve` builds `[unit.microvm]` and `[unit.incus]`, with the same lowest version of podvm (T-123). A guest has no NIC: a front on its egress socket gives the fake broker (`broker.podrunner.test`), and the hosts of `--allow` through the egress module; each other host gets 403. A guest runs no container hooks. `--podnet PATH` holds each unit under `podnet pod`: a step reaches only the hosts of `--allow HOST` (repeat it) through the egress module, and the fake broker on the loopback; only the seccomp hold (`advisory`) is taken now. One line for each job: `ok`, the result of the runner (`failure`, `cancelled`), `failure` with the reason when the job could not start, or `skipped` with its condition. When a job failed, stderr gets the log of each job. Exit 0, or 1 when a job failed. |
| `podrunner source-conformance -- PROGRAM ARGS...` | Run the 12 tests of the source wire against a program that speaks it on stdio (T-104), each in a limit of 60 s; one line for each test. Exit 0 when each passes, else 1. The program must give two offers or more on its first `next`. |
| `podrunner fake-source [--script FILE]` | A fake source (the script of a `fake` source) that speaks the source wire on stdio: a program of the kind `program` for a test (T-101). It ends when stdin ends. |
| `podrunner mint-serve --config FILE` | The remote mint (GitHub #31), on a machine that runs no unit: the source wire over mutual TLS to the pinned keys of the unit hosts (`docs/configuration.md`, "The remote mint"). |
| `podrunner pin-sign --config FILE --seed-file FILE` | The `signer` and `signature` lines of `[pin]`. The seed file holds 64 hex digits (`openssl rand -hex 32`), mode 0600; keep it off the unit host. |

## The control socket

JSON lines on a unix socket of mode 0600. A peer with another uid is
refused. The socket has threads of its own: at most 8 clients at a time
(one more gets `busy`), and 5 s for each exchange, so a silent client
delays no tick of the supervisor. A request is one line, `{"v": 1, "op": ...}`, and the reply is one
line, `{"v": 1, "reply": "ok", "value": ...}` or
`{"v": 1, "reply": "error", "code": ..., "detail": ...}`. The operations:
`version`, `status`, `drain`, `stop`, `capacity`, `clear-degraded`,
`withdraw`. `crates/podrunner/src/control.rs` sits behind the trait
`Handler`, so that `pod-control` of podcrates can replace it with no change
of the wire.

Where units run as the uid of podrunner (a shared principal), the peer
check does not protect the socket from a unit.
